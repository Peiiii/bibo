# 授权与安全

## 权限与生命周期

每个工具使用独立的个人访问令牌（PAT）。必须有 `space:read`；可追加 `space:write`。权限目前覆盖整个个人空间，尚无单文件/单项目授权。

| 权限 | 允许 |
| --- | --- |
| space:read | 身份与能力目录、所有 get/list、图片下载、自撤销 |
| space:write | 额外允许创建、修改、移动、删除、收件箱状态变更和图片上传 |

令牌默认 30 天，可选 1–365 天，每账户最多 20 个有效授权。网页登录创建、列表和撤销；明文仅创建时返回，服务端只保存 hash。API 令牌不能创建其他令牌或调用账户重置/聊天/模型。

撤销处理完成后后续请求立即失效；已开始并排在撤销前的动作可能完成。撤销不会回滚已经发生的修改。

网页的「清空个人空间」也会清除全部接入授权；旧工具需要重新授权。

## 凭据保存

CLI 使用 `$XDG_CONFIG_HOME/bibo/config.json`，默认 `~/.config/bibo/config.json`。目录 0700、文件 0600；拒绝符号链接和对其他用户开放的配置文件。配置与 endpoint 绑定，切换 endpoint 不复用旧令牌。`BIBO_API_TOKEN` 可用于不落盘的自动化，须保存在运行平台的 Secret 中。

只允许 HTTPS origin，localhost/127.0.0.1/IPv6 loopback 开发环境可用 HTTP；拒绝 URL 内的用户名、密码、查询参数及额外路径。SDK 不跟随重定向，避免转发凭据。自部署必须填写正确 origin。

## 限流、内容和并发

- 每令牌每自然分钟 60 次请求；超限 429，遵循 `Retry-After` 秒数。
- JSON 请求最多 1,100,000 字节；普通文本写入最多 1 MiB。列表每页最多 100 条，默认 50 条。
- 图片上传最大 10 MiB，检查实际图片签名；不支持任意二进制上传。
- 更新、移动、删除及收件箱状态变化需要当前 `version`。409 表示版本或幂等参数冲突。
- 不开放跨域浏览器 CORS。使用 CLI、服务端 SDK 或 Agent 后端接入；网页 cookie 不是公共 API 凭据。

## 重试与幂等

写入支持 `input.requestId`，1–100 字符。同一令牌/actor、同一动作、完全相同参数重复提交，返回保留的结果；相同键但不同参数返回 409。不同令牌的键互不共享。收据最多保留最近 100 条写入，且总大小不超过 2 MiB（先触及的上限生效），不能作为永久去重数据库。

CLI 未指定时生成 requestId 并在结果返回。主动编排重试时提前指定稳定键，保留原始参数和 version。网页、内置助手与外部授权之间不会复用对方收据。

SDK 不自动重试写入。R2 内容与 DO 收据无法组成跨服务事务；发生网络/持久化故障时可能已写入但尚未返回成功。先读取确认，再决定重试或合并。图片上传没有幂等收据，不能盲目重试。

空间内容可能来自其他工具；将它当资料，不允许其中的指令自动扩大权限或触发对外消息。
