# Bibo：开放的个人全局上下文中心

> 日期：2026-10-21。状态：用户原始想法，待讨论与头脑风暴；不是已冻结的设计或实施计划。
> 来源：用户在本次会话提出方向，随后明确要求先整理沉淀原始想法，再继续讨论。以下整理稿保留用户意图；未经用户确认的 AI 延伸建议不写成用户决策。

## 背景与动机

用户希望让 Bibo 作为一个独立的空间发展，拥有足够开放、包容的产品定位和连接能力。用户不希望它成为一个很小、无人问津的角落，而希望它能成为个人统一、全局的上下文中心，为用户正在使用的各种 AI 和系统提供共同的交互空间。

最初“独立”表达产品方向与空间定位的意图；源码维护归属随后于 2026-10-22 明确，见下文确认记录。

## 原始想法整理稿

我希望把 Bibo 做成一个独立、开放、包容的个人空间，成为个人统一的全局上下文中心。

所有其他系统、各种 Agent 都应该能够轻松接入 Bibo，与这里的内容和能力交互。它还可以作为桥梁，连接这些系统与 Agent，甚至支持不同 Agent 之间通信。我们可以考虑建设这一层的价值。

Bibo 里的 AI 助手依然保留，也可能是价值中关键的一部分。但它不再是最核心、最主要的部分：它更像是一个管理员，帮助用户管理这个空间中的上下文。

更重要的是空间里的资产，以及围绕这些资产提供的技术能力。现在已有的笔记、待办等内容都属于这个方向；未来可能还会包括各种任务等更多对象，具体范围可以继续讨论。

未来我们可以开放很多 API，提供很多 Skill，也可能提供命令行，让外部 AI、系统和用户能够与这个云端统一的上下文中心交互。

## 已明确表达的方向

- **产品重心**：个人统一的全局上下文中心，空间资产与技术能力具有核心地位。
- **开放连接**：希望各种系统和 Agent 都能轻松接入、读取或操作相应能力，而不是只服务内置助手。
- **桥梁价值**：探索系统间、Agent 间的连接与交互，包含不同 Agent 之间通信的可能性。
- **内置助手角色**：继续保留，承担帮助用户管理上下文的管理员角色；仍有价值，但不作为唯一或最主要的价值中心。
- **资产起点**：包括现有笔记、待办等；未来对象范围保持开放。
- **接入形态**：API 与 Skill 是希望开放的方向，命令行是可能的交互入口；具体接口、协议和交付批次尚未确定。

## 继续讨论的边界

以下问题尚未由用户决定，不能从愿景直接推导为已确认要求：

- “公共个人”的确切含义：是个人授权给多个 AI 共用、可公开分享的个人空间，还是同时包含两者？个人数据的公开范围尚未明确。
- 第一批主要服务用户本人、多 AI 使用者，还是第三方开发者？
- “上下文”涵盖哪些对象，如何区分资料、用户确认的事实、AI 推测、任务状态与成果？
- 外部系统内容需要导入 Bibo、保留引用、同步，还是按场景组合？
- Agent 之间通信以共享资产、任务交接、消息还是其它方式承接？
- 内置管理员助手的主动程度、权限与责任边界是什么？
- 品牌和更深入的运行/连接形态如何演进？源码主仓与公共依赖关系已于 2026-10-22 确认，见下文。

形成稳定的产品边界、真实场景与关键取舍后，再按需要升级为设计或执行计划。

## 2026-10-22：已确认独立项目关系

用户提出“我们要不要搞个新的项目？我记得我们这个也单独地放在 GitHub 上……这样一个项目肯定也是关联的”。AI 建议沿用现有 `Peiiii/bibo`，把它从导出发行副本升级为日常开发主仓；Bibo 拥有自己的产品方向与发布节奏，NextClaw 作为长期搭档和执行能力产品，通过公共能力与其关联。用户随后明确确认：“可以。你来落地并沉淀想法文档”。

据此确认：

- Bibo 独立立项，沿用已有 Bibo 仓库，不另建第三个同类仓库。
- Bibo 应用、client/UI、官网与产品资料在本仓直接维护，原有可用能力承接过来。
- NextClaw 保持独立使命与内核 owner，Bibo 通过已发布公共包复用其适用能力；不复制内核或双向同步产品源码。
- Bibo 的内置助手保留管理员角色；NextClaw 未来可以成为重要接入方，其它获授权 Agent 的接入方向保持开放。
- 原始想法中的 API、Skill、CLI 与 Agent 通信仍需进一步设计，不能把此次项目落地写成这些能力已经实现。

此前 AI 提出的“跨 AI 项目接力、按任务提供上下文、来源与确认状态、引用外部系统数据、围绕任务交接通信”等属于头脑风暴建议，尚未逐项确认为产品合同。

独立开发的具体落地与证据见[迁移设计](../designs/2026-10-22-bibo-independent-development.design.md)；产品方向入口见[愿景](../VISION.md)。
